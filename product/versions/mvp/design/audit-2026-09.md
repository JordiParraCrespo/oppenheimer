# Design export audit — September 2026

What the two export syncs after the port (PR #18 `92fb6e5`, PR #19
`3b70a98`) changed in `version1/`, screen by screen, against what
`@oppenheimer/design-system-web` and `apps/web-showcase` render today. The
bound system under `_ds/` did not change: no token work, this is all
components. Order follows the flow. The last section is the build list.

Legend: **have** = the package already covers it · **change** = an existing
component needs a new prop, part or state · **new** = nothing in the
inventory fits.

## 1. Onboarding chrome (CreateWorkspace, ConnectGitHub, AddHost)

Every onboarding step now opens with the same row: a `← Back` link, a 12px
hairline, and the step counter (`2 of 4` … `4 of 4`, mono eyebrow). The Back
link that used to sit next to the primary button at the foot of AddHost is
gone from there.

- **new** `StepHeader` (or `OnboardingStep`): eyebrow row with the back link,
  the divider and the counter, then the 38px display title and the muted
  lead. Three screens render it identically; today each app screen would
  hand-build it. The counter is `figures` mono uppercase at 11px, the back
  link is `Link` in `fg-muted` with a 14px arrow.

## 2. CreateWorkspace (new screen, step 2 of 4)

Two fields in the `lg` (42px) control size, one primary block button, an
account line ("Using jordi…" + "Use a different account" link), the photo
carousel on the right.

- **have** `Field`, `Input size="lg"`, `Button size="lg" block`, `Link`,
  `ImageCarousel`.
- **change** `Input`: the URL field has a mono **prefix** (`oppenheimer.dev/`)
  inside the border, a mono value, and a **trailing state glyph** that cycles
  through checking (spinner), available (green check) and taken (red ×).
  `leading` / `trailing` slots exist, so this is a documented recipe plus a
  `mono` option for the value, not a new component.
- **change** `Field`: the hint under the URL field changes colour with the
  verdict (`fg-muted` → `success` → `danger`). `FieldDescription` and
  `FieldError` cover two of the three; a **success** state for the hint is
  missing.
- **new** (small) `AvailabilityGlyph` or an `Input` `status` prop
  (`checking | ok | taken`) so the spinner/check/cross is one thing and not
  three inline SVGs.

## 3. AddHost (step 4 of 4)

Same as before apart from the step header (§1) and the copy of the install
command now wrapping with `overflow-wrap: anywhere` instead of breaking
mid-word.

- **have** `CodeBlock` ×2 in `Card`s, `StatusDot pulse`, the token countdown.
- **change** `CodeBlock`: wrap rule to `break-normal overflow-wrap-anywhere`.

## 4. Ready (new screen, replaces FirstSession)

A 52px ring (1.5px primary border on `primary-surface`) holding a check,
animated in with a 320ms scale, then the title, then a three-row summary
card (label muted 13px left, mono value right, hairlines between) and one
primary block button.

- **have** `Card`, `Button`, `ImageCarousel`.
- **new** `SuccessMark` (the ring + check with its enter animation, reduced
  motion honoured). Nothing in the inventory draws it.
- **new** `SummaryList` / `FactRow`: the label–value rows with hairlines,
  value in mono. Also the shape the Ready card, the host row in the Add host
  dialog, and future settings screens share. Could be a `Card` sub-part
  (`CardRow`) rather than a component of its own.

## 5. SessionsConsole — sidebar

The sidebar itself is unchanged in structure: wordmark, "New session" block
button, list head with count and filter icon button, filter chips, session
rows, account row with the drill-down menu.

- **have** `Sidebar`, `SidebarGroupLabel` + `SidebarGroupCount`, `FilterChip`,
  `SessionItem`, `DropdownMenu` (filters, account), `Avatar`.
- **change** `SessionItem`: rows started in this run show a **provisioning
  state** on their row ("announces itself on its sidebar row") — the artboard
  uses the branch glyph pulsing until the session is ready. Add `pending` to
  the row's state treatment (the `StatusState` union already has it) and a
  pulse.
- **change** `SessionItem` name: the row now reads the scope short form
  (`xrp-mobile  +2 · main`) when a session spans several repositories.
  Truncation only; no API change, but the showcase should show it.

## 6. SessionsConsole — New session, the scope row

This is the largest change. All four scope pickers are now **searchable**,
the repository picker is **multi-select with a per-repo branch pane**, the
branch chip is conditional, and the agent picker carries **marks**.

Common to all four listboxes:

- **change** `ChipSelect`: a sticky **search row** at the top of the popup
  (search glyph + borderless 12.5px input, hairline under it, `Search
  hosts…` etc.), an **empty line** (`No host matches.`, 12.5px muted, centred)
  and a fixed popup width (248px; 318px for the repository one) with
  `max-height` 248/264px. Base UI `Select` has no filtering; the package's
  `Combobox` does. Decision needed: rebuild `ChipSelect` on the Combobox
  primitive (single component, chip trigger, searchable list) or add a
  `searchable` mode that swaps the primitive underneath. Either way the
  options and the action row keep their current API.
- **change** `ChipSelectAction` ("Add host…", "Add repository…"): now sits in
  its own footer band (hairline above, 3px inset) with a **leading plus
  icon** and a **trailing chevron**. Add `icon` and `chevron` (or render the
  chevron always for an action that opens something).
- Option density changed: 6px 10px padding, 13px label, 11px description at
  1.35 line height. Adjust `OPTION_CLASSES`.

Host picker:

- **have** after the search change. Descriptions are the host's size, region
  and load (`32 vCPU · eu-west · idle`).

Repository picker:

- **new** multi-select. Rows toggle in and out of the selection; the chip
  reads `<primary>  +N`. Each **selected** row grows a right-hand cell
  (134px, hairline on its left, mono 11px) showing that repo's branch with a
  chevron; clicking it slides the same popup to a **branch pane** for that
  repo: a back row (`‹ Branch for xrp-mobile`), its own search row, mono
  branch options, empty line. Picking a branch returns to the repo list.
  This is a `RepositorySelect` (or `ScopeSelect` with panes) built on the
  searchable `ChipSelect`; Base UI `Select` cannot express it, so it is a
  Combobox/Popover composition. Adding a repo lands it on its default
  branch; removing it forgets its branch.

Branch picker:

- **change** it only renders while exactly one repository is selected
  (`singleRepo`); past that, branches live in the repo rows. Options are
  mono 12px. Nothing to build beyond the search row; the showcase should
  show the conditional.

Agent picker:

- **new** `AgentMark`: the coding-agent logos from `version1/assets/agents/`
  (Claude Code `claude.svg`, OpenCode `opencode.png`; Copilot, Gemini and
  Cursor held in reserve). Codex has no mark on purpose and takes the neutral
  bot glyph; "Blank terminal" takes a terminal glyph. Needs the assets
  copied into the package (an `assets/agents/` folder next to `imagery/`) and
  a component that maps `agent id → mark`, 15px, with the glyph fallback.
- **change** `ChipSelectOption`: a **leading** slot for the mark. Today an
  option is label + description + check only.
- The catalogue grew: Claude Code, Codex, OpenCode, Blank terminal.

## 7. SessionsConsole — composer and model menu

- **have** `Composer`, `DropdownMenu` with `DropdownMenuRadioItem
  description`, the Effort submenu.
- **change** the model menu is now **scoped to the harness**: the eyebrow is
  the agent's name and the list is that agent's models (Claude Code → Opus /
  Sonnet / Haiku, Codex → GPT‑5.2 family, OpenCode → open weights, Blank
  terminal → no picker at all: `hasModel` hides the trigger). Changing the
  agent resets the model to the harness default. This is data and a demo, not
  a component change, but the `ModelMenu` demo in the showcase hard-codes one
  list and should take the harness.
- **have** the trigger (`op-modelbtn`: model name + effort tag) is the
  showcase's `ModelMenu` trigger already.

## 8. SessionsConsole — provisioning and terminal

- **have** `Stepper` (four named steps, elapsed clock, status word) and
  `Terminal` with `TerminalStatusBar`.
- **change** `Stepper` labels now depend on scope: `Clone 3 repositories` /
  `Check out branches` when several repos are selected. Copy only.
- **change** the terminal frame gains a `zoom` state (`framePad` / `frameMax`
  animate between padded and edge-to-edge over 220ms). If the app wants it,
  `Terminal` needs a `zoomed` prop; the showcase does not show it.

## 9. Add host dialog (new, in SessionsConsole and Components)

The one dialog in v1. 440px, 28px radius. Header holds the title **and** the
lead with the close button inline to their right (not absolute in the corner
as `DialogContent` places it today). Body: a label row with a **segmented
pill toggle** (Command / Agent prompt), a **copyable code panel** on
`hover-surface` with a corner icon button that flips to a green check, a
mono token countdown line with a "New token" link, a hairline, and a
52px-tall **status slot** that resolves in place: pulsing dot + "Listening
for this host…" → green dot + `mac-studio` + `macOS 15 · echo 38 ms` +
"git, tmux, claude ready". Footer: secondary Cancel, primary "Use this
host" disabled until the host registers.

- **have** `Dialog*`, `Button`, `IconButton`, `StatusDot pulse`, `Link`.
- **change** `DialogHeader`: a variant where the close button sits in the
  header row beside the title/description stack instead of absolutely
  positioned. Or make `DialogContent showCloseButton={false}` and let
  `DialogHeader` take a `close` slot.
- **new** `SegmentedControl` (two-way pill switch on `hover-surface`, active
  segment on `card`). `ToggleGroup` exists from the starter but is not on
  the inventory and is not this shape; restyle it or add the pill variant.
- **change** `CodeBlock`: a **panel** variant (tonal background, 10px radius,
  corner icon-only copy that flips to a check) as opposed to the current
  header-with-"Copy"-button layout used on AddHost. Same component, second
  layout; both copy states already exist.
- **new** `HostStatusRow` / reuse `SummaryList` (§4): the registered-host
  line. `StatusDot` with `meta` covers the waiting state; the resolved state
  is a row of dot, mono name, muted detail and a right-aligned readiness
  note.
- The whole thing is an `AddHostDialog` feature in `apps/web`
  (`features/hosts/dialogs/`), not a design-system export; the parts above
  are what the system must supply for it.

## 10. Components artboard

The inventory page renamed "Welcome modal" to "Dialog" and now shows the Add

showcase's `DialogDemo` still renders the welcome modal. Chip select is
documented as "pill trigger over a 248px listbox … every one of them
filters … a pinned action at the foot".

- **change** showcase `DialogDemo` → the Add host dialog; keep the
  destructive confirm demo.
- **change** showcase `ScopeChips` → searchable, multi-repo with branch pane,
  agent marks, conditional branch chip.

## Open decisions

1. **ChipSelect primitive**: rewrite on Combobox (one searchable component,
   Base UI `Select` dropped) or keep `Select` and add a searchable mode? A
   rewrite is cleaner and the console is the only caller.
2. **Multi-repo**: is multi-select repository scope in the MVP, or a v2
   affordance the artboard shows early? It decides whether
   `RepositorySelect` is built now or the branch chip stays unconditional.
3. **Agent marks**: the Claude and OpenCode marks are third-party logos
   copied from the Orca repository; confirm they may ship in the package
   (the font review last time rejected redistributing SF Pro).
4. **SummaryList vs CardRow**: standalone component, or rows inside `Card`?
5. **Terminal zoom**: in scope for the MVP console, or leave the prop out?
