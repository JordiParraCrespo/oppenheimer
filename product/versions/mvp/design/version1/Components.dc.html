Group 02

Forms

The four input shapes the product actually uses. Type into a 10px radius; every field shows focus.

Field · Input

op-field · op-label · op-input · op-input--lg

As on the sign-in screen: the label sits above, the field is a 10px-radius shell around a borderless input. Large is the auth size; medium everywhere in the app.

Textarea

op-composer · op-composer__input

The instruction field from the session composer: a 14px-radius pane with no inner border, sized to hold three or four lines before it scrolls.

Chip select

op-chipselect · op-listbox · op-option · search row · footer action

How every scope choice is made in the console — a pill trigger over a 248px listbox. Every one of them filters: a sticky search row on top, a muted second line where the value alone is not enough, and a pinned action at the foot for adding what is not in the list yet.

Menu

op-menu · op-menu__item · __label-text · __value · __shortcut · __sep · data-variant

One menu shape covers the filter, the model picker and the account row. Rows that lead somewhere carry their current value and a › ; nested panes come back with a ‹ .

Group 04

Overlays

The only layers allowed to cast a shadow.

Callout

neutral · info · success · warning · error

A note in the flow, not a card: flat tonal fill, hairline-free, 13px text. It never outweighs the form it sits above, and it never carries a button — if an action is needed, the action lives in the form. Neutral is the default and carries no hue — most notes are explanations, not state. The four tinted variants take a status hue at 11–14% behind full-opacity ink, and only when something actually is in that state.

Group 05

Terminal

The primary surface, not a widget. Carries its own --term-* ramp so 13px mono stays legible on both themes.

SessionItem

name · state · age · active

One 30px line, because there are hundreds. State colours the branch glyph: running green, waiting amber, failed red, idle grey.

Terminal pane

titlebar · name · state dot · host · expand · close

The console frames each session rather than running it full-bleed — a frame implies there can be a second one. The bar carries what the scrollback can't: which host, which branch, still running. Neither control stops the run: expand zooms the pane over the sidebar, close detaches the view.

Composer

scope chips · textarea · attach + permissions · model + effort · dictate · send

Three bands. The chips above the field fix where the work happens — host, repositories, branches. Bottom left is what it may touch: attachments and the permission level — ask for approval, approve for me, or full access, the one level allowed a warning tone because it changes a machine unattended. Bottom right is the engine — one button for harness and model (harness column, its models in a side panel, so the pair is always valid) and effort beside it as a five-stop ramp from faster to smarter.
