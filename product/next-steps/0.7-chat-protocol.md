# 0.7 — The chat's model and protocol

**Goal:** give both chats (bots, and a session over its agent's transcript)
one item model and the protocol habits Codex and Grok share, so the
display work in [`0.7-terminal-and-chat.md`](0.7-terminal-and-chat.md) has
something solid to draw. The read behind it is
[`../research/lessons-from-codex-and-grok-chat.md`](../research/lessons-from-codex-and-grok-chat.md).

## Decided (2026-10-31)

The owner took all six slices drawn from that read. Each is its own pull
request from `main`. Scope says which chat a slice changes: *bots* is the
bots chat, *sessions* the session chat over an agent's transcript.

| # | Slice | Scope | Borrowed from |
|---|-------|-------|---------------|
| 1 | **One chat item model** in `@oppenheimer/shared`: turns of typed items (user and agent message, reasoning, command, file read, search, file change, plan, MCP and other tool calls, subagent, event) that go in progress → completed or failed, with an adapter per chat. Tool classification and labels move to one module both chats use. One renderer is the step after | both | Codex thread / turn / item; Grok `OutputChunk` |
| 2 | **A stream that loses nothing**: the bots stream keeps a running turn's unstored text, sends it as a snapshot when the browser connects, and numbers text frames so the client drops what it already has | bots | Grok's reconnect: snapshot first, then deltas |
| 3 | **Exploration folds and output is bounded**: a run of read-only calls is one "Explored" group with duplicate reads merged; output shows a few lines and "+N lines", the rest one click away | both, sessions first | Codex `ExecCell`, `live_output.rs` |
| 4 | **Approvals as requests**: the server says which decisions a card offers, a decision in one tab closes the card in every other, and a card waits for the sentence in flight | bots | Codex `available_decisions`, `serverRequest/resolved`, `InterruptManager` |
| 5 | **Steer, queue and rewind**: a message sent mid-turn can steer the running turn at its next tool boundary or wait for the next one; the latest prompt can be edited, rewinding the conversation to before it. A session types into the PTY, where the CLI's own queue decides, so it gets none of this | bots | Codex `turn/steer`, `thread/queue/*`, `thread/rollback` |
| 6 | **Tests of what is drawn**: recorded conversations replayed through the real chat components, asserted on behaviour | both | Codex's vt100 snapshot suite |

**Where they touch.** Slices 1 and 3 both reach the tool rows of both chats:
1 owns classification and labels, 3 owns grouping and caps, and whichever
merges second takes the other's shape. Slice 6's assertions are on
behaviour, so the others change its renderers without rewriting it.

**The session chat adapts in the console.** The runner keeps sending
transcript lines (`attachment.chat`), and the console turns them into
items, as `SessionChat` already turns them into typed steps. The model is a
shared type plus one adapter per chat, not a wire change. The runner stays
free of the item model, and the agent's transcript file stays the one
source (`0.7-terminal-and-chat.md`). A reason for the runner to know items
would reopen this.
