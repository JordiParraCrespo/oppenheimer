# 0.7 — The chat's model and protocol

**Goal:** give both chats (bots, and a session over its agent's transcript)
one item model and the protocol habits Codex and Grok share, so the
display work in [`0.7-terminal-and-chat.md`](0.7-terminal-and-chat.md) has
something solid to draw. The read behind it is
[`../research/lessons-from-codex-and-grok-chat.md`](../research/lessons-from-codex-and-grok-chat.md).

## Decided (2026-10-31, the owner: "I like all of them")

Six slices, each its own pull request, each from `main`:

| # | Slice | Borrowed from | Branch |
|---|-------|---------------|--------|
| 1 | **One chat item model** in `@oppenheimer/shared`: turns of typed items (user and agent message, reasoning, command, file read, search, file change, plan, MCP and other tool calls, subagent, event) that go in progress → completed or failed. Adapters from bot messages and Claude Code transcript entries; tool classification and labels move to one module both features use. One renderer is the step after | Codex thread / turn / item; Grok `OutputChunk` | `claude/friendly-curie-ru8zl1-chat-items` |
| 2 | **A stream that loses nothing**: the bots stream keeps a running turn's unstored text, sends it as a snapshot when the browser connects, and numbers text frames so the client drops what it already has | Grok's reconnect: snapshot first, then deltas | `…-stream-snapshot` |
| 3 | **Exploration folds and output is bounded**: a run of read-only calls is one "Explored" group with duplicate reads merged; output shows a few lines and "+N lines", the rest one click away | Codex `ExecCell`, `live_output.rs` | `…-explored` |
| 4 | **Approvals as requests**: the server says which decisions a card offers, a decision in one tab closes the card in every other, and a card waits for the sentence in flight | Codex `available_decisions`, `serverRequest/resolved`, `InterruptManager` | `…-approvals` |
| 5 | **Steer, queue and rewind**: a message sent mid-turn can steer the running turn at its next tool boundary or wait for the next one; the latest prompt can be edited, rewinding the conversation to before it | Codex `turn/steer`, `thread/queue/*`, `thread/rollback` | `…-steer` |
| 6 | **Tests of what is drawn**: recorded conversations replayed through the real chat components, asserted on behaviour | Codex's vt100 snapshot suite | `…-chat-render-tests` |

The slices are independent; where two touch the same files (1 and 3 both
reach the tool rows), the second to merge takes the first's shape.

## Open questions

1. When both chats read the item model, is the session chat's runner still
   sending transcript lines (adapted in the console), or does the runner
   send items? Codex generates its client types from one schema; ours
   would be the Zod schema in `packages/shared`.
2. Does a session (Claude Code in tmux) get steering at all? It types into
   the PTY, where the CLI's own queue decides; slice 5 is the bots chat.
3. Virtualizing the transcript: Codex pages history by turns and items,
   Grok shows no virtual list. Bots draw up to 200 messages; is paging
   enough?
