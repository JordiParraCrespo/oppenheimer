# 0.4 — Slack

**Goal:** the Slack integration. Start and follow sessions from Slack,
and hear from a session in Slack when it needs someone.

## What exists to build on

- Sessions and their event log (`../versions/mvp/10-api-modules-and-data-model.md`).
- The untrusted-payload envelope note 05 §6–§7 proposes for GitHub
  events applies to Slack messages the same way.
- 0.3's cards, if a Slack message can become one.

## Questions to answer first

1. Which direction first: notifications out (session waiting on input,
   PR opened, CI red), or commands in (start a session from a message or
   a thread)?
2. One Slack thread per session, with replies sent into the session?
3. How is a Slack user mapped to an Oppenheimer account, and which
   workspace's sessions can they reach?
4. What in a Slack message is untrusted, and what may the agent act on?
